# LT Dialogue

[![Flutter](https://img.shields.io/badge/Flutter-app-02569B?logo=flutter)](https://flutter.dev/) [![Latest release](https://img.shields.io/github/v/release/yangrunzhi345-blip/LT)](https://github.com/yangrunzhi345-blip/LT/releases/latest)

[English](README.md) | [简体中文](README.zh-CN.md) | [繁體中文](README.zh-TW.md) | [日本語](README.ja.md) | [한국어](README.ko.md)

LT Dialogue は、AI によるインタラクティブな物語、世界観、キャラクターを作るローカル優先のワークベンチです。

再利用できる資料を作り、そのスナップショットから Adventure を開始して、物語とともに変化するキャラクターや世界の状態を確認できます。LT は Flutter、Dart、Riverpod、SQLite を使用しています。

![LT Dialogue ロゴ](logo.png)

## 主な機能

- ストリーミングによるターン生成、行動選択、分岐、保存済みセッションの再開。
- 検索可能な Resource Library と、構造化編集・AI 生成を行う Resource Studio。
- ライブラリから Adventure に引き継がれ、実行中に変化して物語のコンテキストに入るキャラクター関係。
- ダッシュボード、エンティティの状態、タイムライン、ターンごとの変化を確認する Runtime State Hub。
- 翻訳と読み上げ。モデルをダウンロードして使うローカルニューラル TTS も選択可能。
- レスポンシブなナビゲーション。デスクトップのサイドバーには最近の Adventure を表示し、小画面ではコンパクトな操作で Adventure、Resource Library、実行時状態、設定にアクセス。

## インタラクティブ Adventure

作成ウィザードで世界観、主人公、同行キャラクター、NPC を選び、冒頭のシーンを設定して準備状態を確認します。選択したリソースは Adventure 固有のスナップショットになり、後のライブラリ編集が既存の Adventure を黙って書き換えることはありません。

プレイ中は物語のストリーミング、行動選択、分岐の作成、操作キャラクターの切り替え、保存済みセッションの再開に対応します。ブックマーク、メッセージ編集、ダイス判定、会話のインポート・エクスポート、コンテキスト要約で長い物語を支えます。

## Resource Library と Resource Studio

世界観、キャラクターカード、NPC を作成、インポート、検索、絞り込み、管理できます。資料は順序を持つ `Resource → Section → Part` 構造です。

Resource Studio ではセクションの追加・並べ替え、Part の編集、ストリーミング生成、手動保存、自動保存、下書きの復旧ができます。失敗した Part を個別または一括で再試行し、リビジョン履歴の確認と復元を行えます。検証結果と準備状態から Adventure で利用可能かを確認できます。

容量ツールで資料のサイズを確認し、圧縮候補を生成して、確認後に明示的に公開できます。圧縮が現在の内容を自動で置き換えることはありません。ライブラリにはゴミ箱と復元機能もあります。

## キャラクター、関係、実行時状態

ライブラリでキャラクター関係を管理し、既存のキャラクターから関連キャラクターを生成できます。選択したキャラクター同士の関係は Adventure のスナップショットにコピーでき、プレイ中に変化します。現在の関係は物語のコンテキストと重み付きトークン予算計画に入り、関連する変化が後続の AI 生成に影響します。後のライブラリ上の関係編集がこのスナップショットを黙って変更することはありません。

現在の Adventure の Runtime State Hub では、ダッシュボード、キャラクターと世界の状態、場所、勢力、関係、追跡状態、タイムライン、ターン履歴を確認できます。記録された変化やエンティティの履歴を物語と併せて参照できます。

## AI 生成パイプライン

OpenAI-compatible なエンドポイント、モデル、API キーを設定します。リソース作成とインポートでは、計画、ブループリント、候補確認、Part のストリーミング生成、検証を行い、失敗時の復旧と再試行に対応します。各フローに応じて手動入力、貼り付けテキスト、ファイル内容のテキスト参照、既存資料を使えます。

Adventure 生成ではリソースのスナップショット、最近の物語、要約、実行時状態をコンテキスト予算内に組み立てます。構造化された状態出力を解析・検証し、受理した変化を保存して後続ターンに利用します。

## 読み上げとローカルニューラル TTS

標準はシステム TTS です。Enhanced / Neural TTS は任意で選べるモードで、Sherpa/ONNX により端末内で音声を合成します。ニューラルモデルは APK に同梱されず、自動ダウンロードもされません。設定 → 読み上げ → モデル管理から明示的にダウンロードします。モデル管理ではインストール状態、ダウンロード進捗、ディスク使用量を確認し、ダウンロードのキャンセルやモデルの削除ができます。

ナレーターと既定のキャラクターの声を選び、自動配役を有効にするか、キャラクター/NPC の資料詳細で声を割り当てられます。利用できる声と言語はインストールしたモデルによります。ニューラル音声、モデル、実行環境が利用できない場合、使用可能なシステムバックエンドがあればシステム TTS にフォールバックします。

Linux のシステム読み上げは利用可能な Speech Dispatcher を使います。会話の翻訳は設定したテキストモデルが行い、TTS とは独立しています。

## ローカル優先のアーキテクチャ

リソース、Adventure、メッセージ、リビジョン、アプリ設定は主にローカル SQLite に保存されます。API キーはアプリ層で暗号化してローカルに保存します。データベース全体の暗号化や OS の資格情報ストアへの保存を意味しません。

AI テキスト生成と翻訳は、必要なコンテキストを設定したエンドポイントへ送信します。そのサービスはリモートの場合があります。ニューラルモデルのダウンロードにはネットワークが必要ですが、インストール済みのニューラル TTS モデルはローカルで合成できます。ローカル優先の保存は、すべての AI 機能のオフライン動作を意味しません。

## 多言語対応

UI は English、简体中文、繁體中文、日本語、한국어 に対応します。初回起動時または設定で言語を選べます。翻訳ソースは [`lib/l10n/`](lib/l10n/) にあります。

## インストール

### Android Release のダウンロード

[Latest Release](https://github.com/yangrunzhi345-blip/LT/releases/latest) から正式署名された APK をダウンロードしてください。公式のビルド済みリリースは現在 **Android ARM64 / arm64-v8a のみ**です。このリリースフローでは Windows、Linux、macOS、iOS のインストーラーを配布していません。

バージョンごとの詳細と署名・更新の注意点は [`docs/releases/`](docs/releases/) を参照してください。古い Debug 署名ビルドから移行する際、Android の署名規則によりアンインストールが必要な場合は、先にデータをバックアップまたはエクスポートしてください。

### ソースから実行

リポジトリには Android、Linux、Windows、macOS、iOS の開発用プラットフォームプロジェクトがあります。各プラットフォームのツールチェーンが必要で、サービスの利用可否も異なります。現在の Android 設定はネイティブライブラリを ARM64 に制限しています。

Git、Flutter stable、対象プラットフォームのネイティブツールチェーンを用意してください。`pubspec.yaml` の宣言は Dart `>=3.0.0 <4.0.0` ですが、現在の [`pubspec.lock`](pubspec.lock) は **Flutter >=3.44.0 と Dart >=3.12.0 <4.0.0** を要求します。今回確認した環境は Flutter 3.44.8 / Dart 3.12.2 です。

```bash
git clone https://github.com/yangrunzhi345-blip/LT.git
cd LT
flutter pub get
flutter run
```

対象を指定する場合は `flutter devices` で確認し、`flutter run -d <device-id>` を実行します。AI 生成前に初回設定または設定画面でモデルサービスを構成してください。

## 開発

```bash
dart format --output=none --set-exit-if-changed .
flutter analyze
flutter test
```

開発中は対象を絞ったテストを優先してください。CI はフォーマット、静的解析、Flutter テストを確認します。作業規則は [`AGENTS.md`](AGENTS.md) を参照してください。

## プロジェクト構成

- [`lib/features/`](lib/features/): 機能別 UI と関連コード。
- [`lib/application/`](lib/application/): ユースケース、物語のコンテキスト、処理の統合。
- [`lib/domain/`](lib/domain/): ドメイン契約とモデル。
- [`lib/services/`](lib/services/): 永続化、リポジトリ、モデルアクセス、TTS。
- [`lib/core/`](lib/core/): 共通ルーティング、テーマ、UI 基盤。
- [`test/`](test/): 自動テスト。 [`docs/`](docs/): 実装・開発ドキュメント。

既存の Controller、Provider、Screen、Widget ディレクトリもこれらの境界と併存しています。[`lib/main.dart`](lib/main.dart) を入口に、[ドキュメント索引](docs/README.md) を参照してください。
