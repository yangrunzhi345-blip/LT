## Implementation and release gates

Only bump `pubspec.yaml`, clarify the automated release notes and record release
evidence here unless a verified release blocker requires a focused repair.
The existing Gradle ARM64 filter/exclusions and explicit Flutter target remain
authoritative. No TTS resources, native libraries or fallback code are removed.

Required gates: format, `flutter analyze`, TTS targeted tests, full regression,
ARM64 Release build, APK ABI/ELF verification, required runtime dependency and
FFI-symbol inspection, production Release model load/synthesis/playback, model
download/integrity/extraction coverage, previous-APK upgrade with data retention,
diff review/check, push main, new tag/Release and verification of published asset
digest plus remote main and clean worktree. ABI rejection probes must fail for
forbidden architectures, missing ONNX Runtime and mislabeled ELF fixtures.

The existing signing configuration uses the established Android debug certificate.
Changing certificates would break upgrade compatibility; retain the previous
published certificate and never commit its private key.

Runtime verification may use the existing Android 16 x86_64 emulator with ARM64
translation. Report that boundary explicitly; do not claim physical ARM device
testing. Keep models, audio and diagnostic files outside Git.

## Android runtime and upgrade

Verified using the exact Release APK, on Android 16 x86_64 with ARM64 translation.
This is not physical ARM handset testing.

The production UI downloaded the 147,031,220-byte official Kokoro INT8 archive
over HTTP. Its independently measured SHA-256 matched
`a1e94694776049035c4f2c6529f003aaece993c76aae9a78995831c3c4dcafc6`.
The application completed verification/extraction, published `manifest.json`
and displayed one installed model (205 MB).

The initial default GPU/four-core emulator profile crashed in ONNX Runtime
initialization twice. ONNX Runtime bytes are identical to the previous published
APK. Repeating with a two-core SwiftShader profile successfully loaded and
synthesized using the same Release APK; this profile produced no crash log.
The emulator model was restored from a separately verified model installation
after restart; the download evidence comes from the first profile. This is an
environment compatibility limitation, not evidence of testing every ARM device.
No application workaround or replacement runtime was introduced.

The production `af_maple` preview generated a non-silent mono 16-bit PCM WAV at
24,000 Hz: 60,797 frames, 2.533208 seconds, peak 5,941 and 59,424 nonzero samples.
Android MediaPlayer playback completed twice and the owned temporary WAV was
removed. AudioTrack reported 60,797 and 60,796 frames delivered. System TTS was
bound and reported 81 available languages; its separate production preview also
completed (65,173 frames delivered by the Google TTS process). Fallback error
paths passed targeted routing tests. Neural runtime/resources and fallback are
retained. The successful emulator profile's crash log remained empty.

Upgrade test first installed the exact GitHub v1.1.17 APK (its SHA-256 matched
the published asset), then installed v1.1.18 using `adb install -r`: both PASS.
Package identity and certificate match; versionCode increases 20 → 21.
Certificate SHA-256:
`aec6050661f80dbc6d488bb2ae8112d365ae4343bc5b55d5f4ff9aa77d058050`.
Database and shared-preference SHA-256 values were unchanged across installation.
First launch migrated the existing v47 database to v48, preserved all 54 original
tables and non-settings rows, and passed `PRAGMA integrity_check`. Onboarding
changed settings through normal application actions; no data was cleared.
