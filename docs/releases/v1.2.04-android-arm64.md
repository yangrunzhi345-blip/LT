## Fixes in this release

- **Adventure start failed after resource generation.** Runtime entity
  identifiers were validated against an ASCII-only rule, which is stricter than
  every other identity layer (`ResourceId`, `AdventureCharacterIdentity`,
  `AdventureConfig` all accept opaque strings). Real character-card libraries
  contain ids such as `<name>_<creator>` (non-ASCII for CJK cards), so
  `AdventureRepositoryImpl.seedRuntimeEntity` threw `ArgumentError` after the
  adventure row and some runtime entities had already been written — aborting
  the launch with the generic unknown error and leaving a partial adventure.
  The runtime layer now uses one shared id rule (non-empty, bounded, no control
  characters) across the seed, the model-proposal parser and the scene-state
  parser.
- **Legacy `detail_json` compatibility.** `WorldviewSnapshotService` cast
  `snapshot['detail_json']` to a `Map` unconditionally, unlike the freezer and
  the narrative/engine readers. A snapshot whose `detail_json` was stored as
  text aborted Adventure creation; it now degrades to the description fallback.
- **Adventure readiness error classification.** The assembly launch boundary
  reported an `AdventureReadinessGateException` as an unknown error. It now
  surfaces the gate's typed cause, or the stable readiness category, so a
  not-ready resource shows an actionable message instead of 「未知错误」.
